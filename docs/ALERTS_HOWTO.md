# Ինչպես ավելացնել կամ հեռացնել զգուշացում

GitHub-ում բացեք նախագծի արմատային `alerts.json` ֆայլը և սեղմեք մատիտի նշանը՝ **✏️ Edit**։ Փոխեք բովանդակությունը, ստուգեք և սեղմեք **Commit changes**։ Փոփոխությունը հավելվածում հասանելի կլինի կայքի հրապարակման ավարտից հետո։

Ստորև ամբողջական, վավեր JSON-ի **ՍԻՆԹԵՏԻԿ / SYNTHETIC փորձնական օրինակ** է։ Այն իրական ճանապարհորդական զգուշացում չէ։ Մի հրապարակեք այն որպես իրական դեպքի հաղորդագրություն։

```json
{
  "updated_at": "2026-10-20T07:00:00Z",
  "alerts": [
    {
      "id": "synthetic-demo-20261021-1",
      "level": "info",
      "city": "paris",
      "date": "2026-10-21",
      "until": "2026-10-21T18:00:00Z",
      "title_hy": "ՍԻՆԹԵՏԻԿ փորձնական հաղորդագրություն",
      "text_hy": "Սա միայն ցուցադրման ստուգում է․ իրական խափանում կամ վտանգ չի հաղորդվում։",
      "source_url": null,
      "stop_ids": ["synthetic-unknown-stop"],
      "area": { "lat": 48.8656, "lon": 2.3212, "radius_m": 800 },
      "suggestion_hy": "ՍԻՆԹԵՏԻԿ օրինակ․ սա իրական երթուղու փոփոխության առաջարկ չէ։"
    }
  ]
}
```

- `id`-ն եզակի, ոչ դատարկ անուն է։ Նոր հաղորդագրության կամ բովանդակության կարևոր փոփոխության համար տվեք նոր `id`։ Օգտատիրոջ փակած հաղորդագրությունը նույն `id`-ով նորից չի երևա, նույնիսկ եթե տեքստը փոխեք։
- `level`՝ `danger` (կարմիր), `warning` (դեղին) կամ `info` (տեղեկություն)։
- `city`՝ `paris`, `barcelona`, `rome` կամ `null`՝ բոլոր քաղաքների համար։
- `date`՝ իրական օր՝ `YYYY-MM-DD` ձևով, կամ `null`՝ բոլոր օրերի համար։
- `title_hy` և `text_hy`՝ վերնագիր և պարզ տեքստ։
- `source_url`՝ ստուգված հանրային `https://` հղում կամ `null`։ Մի ավելացրեք գաղտնի հղումներ, մուտքանուն կամ գաղտնաբառ։

Երեք նոր դաշտերը պարտադիր չեն։ `stop_ids`-ում գրեք `trip.json`-ից վերցված կանգառների ճշգրիտ `id`-ները՝ որպես տողերի ցանկ։ Անհայտ անունները անտեսվում են․ օրինակի `synthetic-unknown-stop`-ը դիտավորյալ իրական կանգառ չէ։ `area`-ն մոտավոր գոտու կենտրոնն ու շառավիղն է՝ `lat`՝ −90-ից 90, `lon`՝ −180-ից 180, `radius_m`՝ 50-ից 5000 մետր ներառյալ։ Գոտի չունենալու դեպքում գրեք `null` կամ բաց թողեք դաշտը։ Օրինակի կոորդինատներն իրական վտանգ չեն նշում։ `suggestion_hy`-ում գրեք առաջարկվող փոփոխությունը որպես պարզ տեքստ։

`danger` կամ `warning` հաղորդագրության դեպքում ընթացիկ օրվա համապատասխան կանգառները կարելի է բաց թողնել «Բաց թողնել այս կանգառները» կոճակով։ Պլանը ինքնաշխատ չի փոփոխվում։ Կանգառները վերադարձնելու համար օգտագործեք կանգառի կարգավիճակի կոճակը կամ «Վերականգնել օրվա սկզբնական պլանը»։ Գոտին ու կանգառների նշումները վերաբերում են միայն ակտիվ զգուշացումներին։ Հավելվածը վտանգ չի գուշակում․ ցուցադրում է միայն ֆայլի հրապարակված տեղեկությունը։

`updated_at`-ը ամեն խմբագրման պահին փոխեք իրական թարմացման ժամով։ Ժամանակը գրեք ամբողջությամբ՝ օրինակ `2026-10-20T09:00:00+02:00` կամ նույն պահը UTC-ով՝ `2026-10-20T07:00:00Z`։ `Z`-ը UTC է։ `+02:00`-ը UTC-ից երկու ժամ առաջ է․ այն ընտրեք տվյալ օրվա և վայրի համար, քանի որ ամառային/ձմեռային ժամի անցումից շեղումը կարող է փոխվել։ Մի գրեք ժամ առանց `Z`-ի կամ բացահայտ շեղման։

`until`-ը նույն ձևաչափով ավարտի պահն է։ Այդ պահին և դրանից հետո հաղորդագրությունը չի ցուցադրվի՝ ըստ սարքի ժամի։ `null`-ը նշանակում է՝ ավտոմատ ավարտ չկա։ Հին, արդեն ավարտված հաղորդագրությունը ֆայլում կարող է մնալ, բայց ցանկում չի երևա։ Օրինակի ժամկետները փորձնական են․ իրական հաղորդագրության համար ընտրեք համապատասխան պահերը։

Բոլոր հաղորդագրությունները հեռացնելու համար պահեք դատարկ ցանկ և թարմացրեք ժամը։ Օրինակ՝

```json
{
  "updated_at": "2026-10-20T07:00:00Z",
  "alerts": []
}
```

Միայն մեկ հաղորդագրություն հեռացնելու համար հեռացրեք դրա ամբողջ `{ ... }` բաժինը և կարգավորեք բաժինների միջև ստորակետերը։ JSON-ում մեկնաբանություններ և վերջին տարրից հետո ստորակետ չեն թույլատրվում։ Բանալիներն ու տեքստերը վերցրեք կրկնակի չակերտների մեջ, իսկ `null`-ը գրեք առանց չակերտների։

Եթե համակարգչում կա Node.js, նախագծի պանակից կարող եք ստուգել և՛ JSON-ի շարահյուսությունը, և՛ կառուցվածքը՝

```sh
node --input-type=module -e "import fs from 'node:fs'; import {validateAlerts} from './lib/alerts.js'; validateAlerts(JSON.parse(fs.readFileSync('alerts.json','utf8'))); console.log('OK');"
```

Այլապես հրապարակումից հետո հավելվածում ստուգեք համապատասխան քաղաքն ու օրը, վերնագիրը և «Թարմացված» ժամը։ Սխալ JSON-ը կամ կառուցվածքը հավելվածը չի ընդունի․ կպահի վերջին վավեր տարբերակը։ Հին հաղորդագրության երևալը նոր ֆայլի հաջող ընդունման ապացույց չէ։

Հավելվածը նոր տարբերակը փորձում է ստանալ բացվելիս, էջին վերադառնալիս, կապը վերականգնվելիս և տեսանելի էջում ամեն 5 րոպեն մեկ։ «Թարմացնել տվյալները» սեղմել պետք չէ․ այդ կոճակը ճանապարհորդության հիմնական տվյալների համար է։

Առանձին առցանց/անցանց ռեժիմի կոճակ չկա։ Կապի վիճակը որոշվում է ինքնաշխատ՝ զննարկչի `navigator.onLine` ցուցիչով, `online`/`offline` իրադարձություններով և բեռնման արդյունքներով։ Անցանց վիճակում երևում է վերջին պահպանված վավեր տարբերակը՝ համապատասխան նշումով։ Արտաքին կենդանի հղումների համար ինտերնետ է անհրաժեշտ։
